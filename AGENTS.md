# Инструкции для монорепозитория

## Структура проекта

- `apps/web` — Next.js с App Router; дополнительные правила находятся в `apps/web/AGENTS.md`.
- `apps/admin` — приложение Vite и React.
- `packages/ui` — общие компоненты, стили и утилиты, доступные через `@workspace/ui`.
- `packages/eslint-config` и `packages/eslint-config-next` содержат общие настройки ESLint для Vite и Next.js соответственно.
- Используй pnpm и команды из корневого `package.json`. Общие настройки Prettier и базовый TypeScript-конфиг находятся в корне; настройки конкретных приложений сохраняй в соответствующих пакетах.
- Код, используемый одним приложением, размещай в нём. Изменения в общем пакете проверяй с учётом всех приложений, которые его используют.

## Объём изменений

Вноси только минимальные изменения, необходимые для полного и корректного выполнения задачи. Не добавляй несвязанную функциональность, зависимости, абстракции или попутный рефакторинг. Сохраняй существующее поведение, оформление незатронутого кода и изменения пользователя; необходимые изменения соседнего кода ограничивай решением задачи. Перед завершением проверь дифф и убедись, что каждое изменение обосновано задачей.

## Компоненты интерфейса

Для стандартных элементов интерфейса, таких как поля ввода, кнопки, диалоги и выпадающие списки, сначала используй уже добавленные компоненты shadcn из `packages/ui/src/components/`. Если нужного компонента в проекте нет, добавь его из shadcn с учётом существующей конфигурации проекта и доработай под задачу. Не создавай самодельную замену, когда подходящий компонент shadcn доступен. Если подходящего компонента нет, согласуй решение с пользователем.

## Проверка

- Используй подходящие команды из корня проекта: `pnpm lint`, `pnpm typecheck`, `pnpm format:check`, `pnpm build`; для отдельного приложения применяй `pnpm --filter <имя>`. Запускай только проверки, соответствующие изменению.
- Перед запуском форматирования проверь область действия команды. Не форматируй несвязанные файлы без требования задачи.

## Качество кода

- Перед реализацией изучай относящийся к задаче код и похожие решения в проекте. Переиспользуй существующие компоненты и логику, следуй принятым подходам и не дублируй их без необходимости.
- Используй семантические HTML-элементы, подписи полей, видимый фокус и управление с клавиатуры.
- Давай понятные имена, выделяй повторяющуюся логику при реальной необходимости и в комментариях объясняй причины неочевидных решений, а не пересказывай код.
