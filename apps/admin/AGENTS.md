# Инструкции для админки

Общие правила монорепозитория находятся в корневом `AGENTS.md`.

## Навыки проекта

Перед написанием или изменением кода проверь навыки в `apps/admin/.agents/skills/`: изучи описания в файлах `SKILL.md`, определи применимые к задаче и прочитай их инструкции, а также необходимые материалы, на которые они ссылаются. Следуй этим инструкциям при выполнении задачи. Явные указания пользователя имеют приоритет.

## Дизайн и анимации

- Перед созданием или изменением визуальных компонентов и экранов админки прочитай корневой `design.md` и строго следуй его принципам. Явные указания пользователя для текущей задачи имеют приоритет.
- Создавай выразительный, современный дизайн, соответствующий задаче и продукту. Используй компоненты shadcn и существующие CSS-переменные как основу, адаптируя их внешний вид под проект.
- Поддерживай понятную визуальную иерархию, читаемый контраст, согласованные отступы и типографику, заметные состояния интерактивных элементов и единый характер эффектов.
- Обеспечивай адаптивность на всём диапазоне ширин: смартфоны, планшеты, ноутбуки и большие экраны. Учитывай переполнение, читаемость и удобство нажатия на сенсорных устройствах.
- Используй преимущественно умеренные анимации для обратной связи, переходов и направления внимания; более выразительные эффекты добавляй там, где они уместны. Избегай ненужных бесконечных анимаций и задержек в работе интерфейса.
- Учитывай `prefers-reduced-motion`: заменяй выразительные анимации спокойными переходами или статичными состояниями. Интерфейс должен оставаться работоспособным без декоративных эффектов.
- При изменении интерфейса проверяй его в браузере на нескольких ширинах, включая смартфон, планшет и десктоп. Проверяй уменьшение движения и, при использовании шейдера, состояние без WebGPU. Если браузерная проверка недоступна, укажи это в отчёте.

## Структура кода

- Размещай код раздела рядом с местом использования. Компоненты, утилиты и другую логику, общие для админки, размещай внутри `apps/admin/src`.
- Код, общий для нескольких приложений, размещай в подходящем пакете монорепозитория.
- Псевдоним `@/` указывает на `apps/admin/src/`. Для общих компонентов и утилит используй `@workspace/ui`.

## Стек и маршрутизация

- Основа приложения — Vite, React и TypeScript. Используй общие компоненты и стили из `@workspace/ui`.
- Для маршрутизации используй TanStack Router с файловыми маршрутами.
- TanStack Router, TanStack Query, ofetch, React Hook Form и Zod выбраны для админки, но пока не установлены. Добавляй необходимые зависимости при реализации задачи, которая их требует.

## Данные и состояние

- Используй ofetch для HTTP-запросов, а TanStack Query — для загрузки, кеширования и обновления серверных данных.
- Общие настройки API и обработку ошибок размещай внутри `apps/admin/src`; запросы отдельного раздела — рядом с его кодом.
- Авторизацию, формат ошибок, сроки кеширования и повторы запросов определяй по контракту API и требованиям конкретной задачи.
- Для состояния интерфейса используй состояние и контекст React. Отдельную глобальную библиотеку состояния пока не выбирай.

## Формы и валидация

- Для форм и валидации используй React Hook Form и Zod.
- Проверяй внешние данные на границах приложения, включая ответы API, данные форм, параметры URL и переменные окружения. Некорректные данные считай ошибкой и не передавай дальше в интерфейс; уже проверенные внутренние данные не нужно повторно проверять на каждом шаге.
